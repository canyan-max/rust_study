## 独立复写计划

状态：未开始。计划使用新模块 src/exercises/frame_rewrite.rs，开始时再创建。现有练习保留供完成后对照。

沿用现有 AA55 协议，先不换格式。允许查 API、方法签名和笔记，不复制旧函数正文；CRC 算法可以复用，重点是正确接入。

### 1. 写清接口和布局

- 先用注释写出帧格式、长度含义、CRC 范围和字节序。
- 自己设计错误枚举和函数签名，说明返回拥有的数据还是借用。
- 卡住时参考接口：pack(&[u8]) -> Result<Vec<u8>, FrameError>，unpack(&[u8]) -> Result<&[u8], FrameError>。

验收：能说明数据 N 字节、整帧 N + 5，以及返回切片依赖输入的存活时间。

### 2. 独立组包

- 检查数据长度不超过 255，依次写入帧头、长度、数据和 CRC。
- 固定样例：数据 01 02 03，预期完整帧 AA 55 03 01 02 03 04 F8。
- 边界：0 字节允许、255 字节允许、256 字节拒绝。

验收：测试内容和长度；能解释 Vec 所有权返回给谁，为什么检查后才能 as u8。

### 3. 独立解析单帧

- 读取前检查长度，识别帧头，确认整帧含 CRC 已收齐，校验后返回 payload 切片。
- 输入后面还有数据时，只解析第一帧。
- 测试正常往返、头部不足、数据或 CRC 未收齐、帧头错误、数据改坏后的 CRC 错误。

验收：能指出每次索引对应的长度检查；测试指定错误种类，成功预期遇到错误必须失败。

### 4. 处理连续字节流

- 先用普通函数接收 &mut Vec<u8>，实现半帧保留、整帧移除、坏帧重新寻找帧头。
- 覆盖完整帧 + 半帧、分批补齐、杂乱字节 + 正常帧、坏 CRC 帧 + 正常帧。
- 追加到同一缓冲区，不用赋新 Vec 覆盖残余；错误时应消费字节或等待退出，避免空转。

验收：检查剩余缓冲区并观察业务日志；能解释借用结束后才能修改 Vec，半帧不能随意 clear。

### 5. 可选封装，再接串口

- 若封装，自己写 FrameBuffer 的创建、追加与处理方法；不强制加层。
- 只追加本次 read 返回的 [..count]，超时继续等待，其他错误明确报告并退出或上交。
- 实测一整帧、分两批发送、两帧连续发送。

验收：能区分关联函数、实例方法、Vec 字段的方法；正确接收后再恢复线程学习。

## 复写的推进方式

- 一次只完成一个小步骤，审核后再标记完成，不要求一次写完。
- 可以问具体报错；优先给一个提示或一个方法，不默认提供完整答案。
- 记录需要提示的原因：类型、所有权、语法还是 API 不熟；后续只针对薄弱点短练。
- 测试通过与理解程度分别判断：应能解释行为并独立修改，不要求背出所有方法名。
- 自动断言业务结果交付留待后续，不能把“缓存清空”等同于“正确交付测量值”。
