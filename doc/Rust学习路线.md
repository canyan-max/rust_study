# Rust 学习路线

更新日期：2026-11-21

目标：能独立理解、修改 Windows 串口工具；MCU 继续用 C。

## 当前完成到哪里

minigrep、A8 协议独立复写、同步串口接入和 Measurement 收发已经跑通。近期练习了 Option、累计统计、Instant 计时、线程参数以及命令行 Config。详细成果和验证范围见 [学习进度](学习进度.md)。

## 下次从这里开始

先完善 main.rs 已写好的参数解析，一次只改一个点：

1. 将 parges_args 改名为 parse_args，buard 改为 baud_rate；参数改为 &[String]，调用仍用 &args。理解这里只借用参数列表。
2. 解析函数统一返回错误，main 统一打印。使用 format!("波特率格式错误：{}", error) 保留转换错误原因，复习 format! 返回 String。
3. 给参数解析补三个小测试：COM14 / 9600 成功、缺少参数失败、波特率不是数字失败。成功时检查两个字段，无需连接硬件。
4. 手动运行正确参数，确认串口工具仍能收发；参数错误时应给出提示并停止启动串口。

本轮先不引入新的架构。波特率 0 等业务校验按实际需要补充，不把能解析成 u32 等同于设备一定支持。

## 接下来的方向

- 参数解析稳定后，处理串口打开失败：将 expect 改为可读错误提示，复用 Result 和提前返回。
- 按实际需求选择保存测量记录或整理串口配置；先明确要看到什么结果再写。
- 需要让主线程同时做其他工作时，再继续线程、move、通道和停止机制。
- Tokio、复杂泛型和 GUI 暂缓，不为使用新语法扩大项目。

## 学习方式

- 学习者先写；先给 API、签名和验收目标，需要时再给短示例。
- “检查”默认读取和运行相关测试，不默认代改。
- 方法用到再查，先判断接收类型、返回类型、是否修改或移动数据。
- 卡住时写明中间变量类型，区分容器、元素、引用和 Result/Option。
- 测试覆盖本次行为和必要边界，不重复堆数量。
