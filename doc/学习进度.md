## minigrep 保留的实现

- 代码：src/minigrep.rs；入口：minigrep_start()。
- Config 拥有 query 和 file_path 两个 String。
- parse_args(&[String]) -> Result<Config, String>：总参数必须为 3，含程序自身。
- search/search_case_insensitive：返回 Vec<&str>，结果借自 contents。
- search_file(&Config) -> Result<(), std::io::Error>：读取文件、选择模式、打印匹配行；? 传播读取错误。
- env::var("CASE_SENSITIVE").is_ok()：读到变量时区分大小写，否则忽略大小写；值设为 0 也会启用。
- minigrep_start：获取参数，错误写 stderr 并以 1 退出，正常结束为 0。
- search_with_line_number：返回 Vec<(usize, &str)>，固定忽略大小写，仅作独立练习，未接入主流程。
- 早期第四个参数 --case-sensitive 已取消。

### 常用命令

在工程根目录运行，修改后先保存：

```powershell
cargo run -- at32 sample.txt
$env:CASE_SENSITIVE = "1"
cargo run -- at32 sample.txt
Remove-Item Env:CASE_SENSITIVE
cargo run -- AT32 missing.txt > result.txt
$LASTEXITCODE
cargo test
```

Remove-Item 用于已设置该环境变量的情况。相对文件路径从运行时工作目录解析；cargo run 的 -- 将后续参数明确传给程序。退出码应在对应命令之后立即检查。

## 学习方式与待巩固点

- 有 C/AT32 裸机基础，MCU 工程继续用 C；当前 Windows 编辑器为 Zed。
- 每次一个小点，提供需要的方法、参数、返回类型与验收条件，由学习者手写；明确问怎么写时再给短示例。
- 库方法用到再查，关注接收类型、返回类型、是否修改或消耗原数据，不背标准库。
- 学习者自评所有权和借用基本能判断，主要需要熟悉不同语法表达同一目的；优先用熟悉的循环、match 和明确类型对照。
- 容易混淆 where 的 T:、路径 ::、整个 Result 与内部值、match 分支类型；相关报错已整理进复盘笔记。
- 测试中预期成功却遇到 Err 时用 panic，避免打印后 return 造成假通过。
- 优先 Rust 基础，不扩展设备架构，不为教学容器反复增加方法。
- 询问不代表授权改代码；记笔记、提交推送按明确请求执行。
